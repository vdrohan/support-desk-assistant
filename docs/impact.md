## Phase 1: corpus and retrieval

- **Built:** a polite canada.ca crawler, a chunk -> embed -> index pipeline into Qdrant, a search CLI (`sda-search`) and a retrieval eval runner (`sda-eval-retrieval`) with a versioned question set.
- **How:** protego for robots.txt, BeautifulSoup + markdownify for content; heading-aware chunking (target about 350 tokens, hard max 600, counted with voyage-4's tokenizer) with within-page dedup; `voyage-4` embeddings (1024-dim float, asymmetric `input_type`, SQLite embedding cache); Qdrant collection `canada_docs_v1` with deterministic IDs and a mass-delete guard; page-hit and answer-hit metrics, unfiltered and oracle-filtered by program.
- **Result:** corpus of 129 pages across 5 programs (cpp 30, ei 30, passport 30, oas 28, sin 11). The current corpus chunks to 735 chunks (median 229 tokens, max 600, 0 over max); dedup dropped 1,702 repeated blocks on 29 pages, and passport went from 445 to 204 chunks. First full embedding run: 174k tokens; re-runs on an unchanged corpus: 0. Qdrant point count: not verified in this pass (decision 10 says about 735 points). Retrieval baseline on `retrieval_v1` (37 questions, n = 34 answerable, k = 5): unfiltered page_hit@5 0.912, answer_hit@5 0.882, page_hit@1 0.647; oracle page_hit@5 0.912, answer_hit@5 0.882, page_hit@1 0.676.
- **Evidence:** `wc -l data/manifest.jsonl` and its `program` field; in-memory `chunk_corpus` run (same code path as `uv run sda-ingest --dry-run`, no API calls); `docs/decisions.md` #9 (dedup, passport 445 -> 204), #10 (174k tokens, re-runs 0), #11, #12; `data/eval/retrieval_v1.jsonl`; `data/eval/results/canada_docs_v1_2026-10-08.json` (`metrics.*.overall`); commits 9e4174c (crawler), 9d7ef80 (chunk, embed, index, search), 06485c3 (eval set and runner), 17e7a55 (baseline results at a clean commit).

## Answer eval set v1

- **Built:** a 58-question answer eval set and offline tooling to draft, review and accept candidates, including review from a phone.
- **How:** `sda-eval-draft` drafts candidates with `claude-haiku-5-5`; `check_candidate` requires every key fact to appear verbatim on a gold page before a candidate can be accepted; `sda-eval-review` runs in the terminal or exports one self-contained HTML file for phone review, and `--apply` replays decisions idempotently. Scoring design decided (hybrid: normalized substring match for numbers and codes, a Haiku rubric for sentence facts, deterministic citation and abstention checks, reported per category). The scoring runner `sda-eval-answers` now exists: a free number check decides short numeric facts and anything else goes to a `claude-haiku-5-5` judge (one call per item, cached), with deterministic citation, decoy and abstention checks and a per-category report; it is a dry run by default (`--yes` to call Claude), with a spend cap (`spend_cap_cad`, CA$0.25) checked before and during a run, and an offline hand-review export of judge verdicts (extended below). Its tests are offline (fake Anthropic, fake Voyage, in-memory Qdrant). It has not been run against the API yet.
- **Result:** 66 candidates reviewed: 58 accepted, 8 rejected, 0 pending. The first candidate file had 46 items; 20 were added during review and 6 of the first 46 were reworked. Accepted mix: single_page 32, multi_page 8, confusable 6, unanswerable_out_of_scope 6, unanswerable_in_domain 3, time_sensitive 3. Ids `ev-001` to `ev-058`, unique and contiguous. 7 accepted questions are the maintainer's raw questions, same text as in `data/eval/human_questions.txt` (typos kept, e.g. `ev-047`, `ev-058`). `check_candidate` on all 58: 0 problems. Highest question-pair word Jaccard: 0.40 (`ev-045` vs `ev-058`), against a near-duplicate threshold of 0.7. Answer accuracy: Pending: baseline run.
- **Evidence:** `data/eval/eval_set_v1.jsonl`; `data/eval/review_state.json` and `data/eval/candidates.jsonl` (gitignored working files); `check_candidate` and `jaccard` from `src/support_desk_assistant/evals/draft_questions.py` run over the set on 2026-10-12; `EvalSettings` in `src/support_desk_assistant/config.py`; `docs/decisions.md` #19, #20 and #21; commits c6c3fbe (drafting and review tooling), 207bc53 (drafter prompt rules), 7259776 (eval set v1, decision 20); scoring runner (`src/support_desk_assistant/evals/answers.py`, `prompts/eval_judge.md`, `tests/test_eval_answers.py`, `tests/test_eval_answers_runner.py`): uncommitted at time of writing.

## Answer scoring runner and judge calibration

- **Built:** an extended `sda-eval-answers` that reports overall, per-program, abstention, citation and failure-attribution rows with small-sample intervals, records a reproducibility block with every run, enforces a hard spend cap, and measures the LLM judge against blind human labels.
- **How:** `evals/stats.py` (Wilson interval, confusion counts, Cohen's kappa); `evals/breakdown.py` (overall micro with macro beside it, answerable and abstention never blended; by program via a manifest join; abstention precision and recall with "should abstain" as the positive class; citation validity over non-abstained status-ok answers; failure attribution); `evals/provenance.py` (git sha, dirty flag and diff hash, dataset and manifest hashes, Qdrant points count, prompt hashes, models and profiles, scorer-config hash, SDK versions); `evals/calibrate.py` (blind sheet import into `data/eval/judge_calibration.jsonl`, judge replay with the exact production message, agreement, kappa, false present vs false absent, drift, a provisional warning below 30 labels). Each run writes `.jsonl`, `.summary.json` and `.md` under a UTC run id; tokens and both spent and list cost are reported in CAD; dirty-tree runs go to the gitignored `runs/` unless `--allow-dirty`. All tests are offline (fake Anthropic, fake Voyage, in-memory Qdrant).

Program n for answerable items: ei 14, cpp 11, sin 10, oas 8, passport 7 (one item spans two programs). Answer scores, abstention and citation rates, failure split, judge agreement and cost per run: Pending: baseline run. Human calibration labels: none yet.

## Answer eval run 2: judge audit and reason-first fix

- **Built:** an audit of the run 1 LLM judge against an independent re-grade, one fix to the judge's output schema, and a controlled re-run on the cached answers.
- **How:** a Claude session re-graded all 52 judge-decided facts of run 1 without seeing the verdicts, then compared; the maintainer reviewed the contested rows. Of 4 disagreements (all judge "missing" where the grader said "present"), 2 had a judge reason that concluded "present" next to a false verdict, because `JudgeItem` asked for `present` before `reason`. Fix (decision 25): `reason` first, `judge_schema_version` 1 to 2. Re-run `uv run sda-eval-answers --yes` from a clean tree at commit 23ad7d0, run id 20261019T174456Z: 58 of 58 answers from the cache (answer prompt sha256 f321d36efe9c and dataset sha256 33cfa30622f3 unchanged, answer text identical), 38 judge calls, 0 judge cache hits, judge prompt sha256 83c3c9c7ac00 to 1f1d574ffa27. Only the judge changed, so every difference is attributable to it.
- **Result:** answerable pass 40 of 49 = 0.82 [0.69, 0.90] (run 1: 38 of 49 = 0.78 [0.64, 0.87]); macro 0.79; abstention recall unchanged at 4 of 9 = 0.44 [0.19, 0.73]. Item level: ev-006, ev-021 and ev-033 flipped from fail to pass, ev-011 from pass to fail. Fact level: 5 verdicts changed, 4 "missing" to "present" (all four audit errors) and 1 "present" to "missing" (ev-011[0], a regression the maintainer judged a judge error).
